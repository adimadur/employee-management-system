# 8. Employee List and Create Endpoints

Status: Not Started  
Mandatory: Yes  
Depends On: Task 7

## Goal

Implement the employee collection endpoints for listing and creating employees with backend-enforced validation and permissions.

## Confirmed Current Behavior

- No `GET /api/employees` endpoint exists.
- No `POST /api/employees` endpoint exists.
- Search, filtering, sorting, and pagination are not implemented anywhere yet.

## Implementation Scope

- Add `GET /api/employees` for Super Admin and HR Manager with server-side pagination.
- Add search by name/email, department filter, role filter, status filter, and safe sorting.
- Add `POST /api/employees` with duplicate checks, password hashing, and role assignment restrictions.
- Enforce that only Super Admin can assign `SUPER_ADMIN`.
- Keep manager assignment clear and permission-safe during creation.

## Files Expected To Change

- `backend/src/routes/employee.routes.ts`
- `backend/src/controllers/employee.controller.ts`
- `backend/src/services/employee.service.ts`
- `backend/src/middlewares/validate.ts`

## Acceptance Criteria

- `GET /api/employees` returns the documented paginated response shape.
- Deleted employees are excluded from list results and counts.
- `POST /api/employees` hashes the incoming password and returns a safe employee payload.
- HR Manager cannot create a Super Admin.
- Duplicate email and employee ID conflicts are returned cleanly.
