# 9. Employee Detail, Update, and Self-Edit Restrictions

Status: Not Started  
Mandatory: Yes  
Depends On: Task 8

## Goal

Implement employee detail and update behavior, including the restricted self-edit path for the `EMPLOYEE` role.

## Confirmed Current Behavior

- No `GET /api/employees/:id` endpoint exists.
- No `PUT /api/employees/:id` endpoint exists.
- No backend enforcement exists yet for employee self-edit field limits.

## Implementation Scope

- Add employee detail read behavior for Super Admin, HR Manager, and self-only employee access.
- Add update behavior that uses explicit field allowlists instead of passing request bodies directly into Prisma.
- Enforce HR restrictions around existing Super Admin records and `SUPER_ADMIN` role assignment.
- Enforce employee self-update to only `phone` and `profileImageUrl`.
- Reject or strip unauthorized fields explicitly and document the chosen behavior.

## Files Expected To Change

- `backend/src/controllers/employee.controller.ts`
- `backend/src/services/employee.service.ts`
- `backend/src/routes/employee.routes.ts`
- `backend/src/schemas/employee.schema.ts`

## Acceptance Criteria

- Super Admin and HR Manager can read any non-deleted employee.
- Employee role can read only its own record.
- Employee role can update only `phone` and `profileImageUrl`.
- HR Manager cannot demote or edit an existing Super Admin in forbidden ways.
- Responses remain safely serialized and do not expose internal fields.
