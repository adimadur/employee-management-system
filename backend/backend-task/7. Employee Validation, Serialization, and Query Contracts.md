# 7. Employee Validation, Serialization, and Query Contracts

Status: Not Started  
Mandatory: Yes  
Depends On: Tasks 2, 4, 6

## Goal

Create the backend contracts that employee endpoints will share: Zod validation, serialization, field allowlists, and pagination/query parsing.

## Confirmed Current Behavior

- No employee Zod schemas exist yet.
- No employee serializer exists to remove sensitive fields and normalize salary.
- No shared pagination or list-query parser exists.

## Implementation Scope

- Add Zod schemas for employee create, employee update, self-update, list query params, ID params, and manager assignment.
- Add a reusable employee serializer that strips `passwordHash` and normalizes relation payloads.
- Add pagination helpers and list-query parsing with explicit sort allowlists.
- Define role-based field allowlists for Super Admin, HR Manager, and self-editing employees.
- Keep backend validation authoritative and explicit.

## Files Expected To Change

- `backend/src/schemas/employee.schema.ts`
- `backend/src/schemas/organization.schema.ts`
- `backend/src/utils/pagination.ts`
- `backend/src/types/api.ts`
- `backend/src/services/employee.service.ts`

## Acceptance Criteria

- Validation covers body, params, and query contracts required by later employee endpoints.
- Employee responses never leak `passwordHash`.
- Salary serialization is consistent across all employee responses.
- Sort fields and page size are constrained through an allowlist.
- Self-edit rules are documented in code before update endpoints are written.
