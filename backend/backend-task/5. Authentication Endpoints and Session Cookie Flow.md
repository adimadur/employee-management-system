# 5. Authentication Endpoints and Session Cookie Flow

Status: Not Started  
Mandatory: Yes  
Depends On: Tasks 2, 3, 4

## Goal

Implement `POST /api/auth/login`, `POST /api/auth/logout`, and `GET /api/auth/me` with JWT cookie auth and safe user serialization.

## Confirmed Current Behavior

- No auth routes or controllers exist.
- No JWT helper, login schema, or current-user serializer exists.
- No session cookie behavior is implemented.

## Implementation Scope

- Add auth schemas and controller/service flow for login, logout, and current-user lookup.
- Normalize email before lookup and reject deleted or inactive accounts.
- Compare passwords with bcrypt and issue a minimal JWT payload.
- Set and clear the HTTP-only auth cookie with environment-aware options.
- Return a safe user payload without `passwordHash`.

## Files Expected To Change

- `backend/src/routes/auth.routes.ts`
- `backend/src/controllers/auth.controller.ts`
- `backend/src/services/auth.service.ts`
- `backend/src/schemas/auth.schema.ts`
- `backend/src/utils/jwt.ts`
- `backend/src/types/auth.ts`

## Acceptance Criteria

- Login works for a seeded active user with valid credentials.
- Invalid credentials return a generic failure message.
- Deleted or inactive employees cannot authenticate.
- Logout clears the cookie using matching cookie settings.
- `GET /api/auth/me` returns the safe current-user payload when authenticated.
