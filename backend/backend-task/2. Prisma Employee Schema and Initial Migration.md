# 2. Prisma Employee Schema and Initial Migration

Status: Not Started  
Mandatory: Yes  
Depends On: Task 1

## Goal

Define the canonical `Employee` data model, enums, relations, and indexes in Prisma, then create the initial migration.

## Confirmed Current Behavior

- No Prisma schema exists.
- The database contract from `backend/backend.AGENTS.md` is not yet encoded in code.
- No migration or generated Prisma client exists.

## Implementation Scope

- Add Prisma datasource and generator configuration.
- Define `EmployeeRole` and `EmployeeStatus` enums.
- Define the `Employee` model with login fields, profile fields, role/status fields, hierarchy relation, timestamps, and `deletedAt`.
- Add the recommended indexes and unique constraints.
- Decide and document how salary serialization will work in the API.
- Create the initial migration and Prisma client generation flow.

## Files Expected To Change

- `backend/prisma/schema.prisma`
- `backend/prisma/migrations/`
- `backend/src/types/`
- `backend/README.md`

## Acceptance Criteria

- Prisma schema matches the repository instructions for the employee model and hierarchy relation.
- Unique constraints protect `employeeId` and `email`.
- Soft delete and manager relation are represented in schema, not only in application logic.
- The initial migration can be applied to a PostgreSQL database.

## Verification

- `npx prisma validate`
- `npx prisma generate`
- `npx prisma migrate dev --name init`
