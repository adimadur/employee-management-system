# 6. Authentication Middleware and RBAC Guards

Status: Not Started  
Mandatory: Yes  
Depends On: Tasks 4, 5

## Goal

Add reusable auth and authorization middleware so every protected route can enforce backend security consistently.

## Confirmed Current Behavior

- No `authenticate` middleware exists to read the cookie and load the employee.
- No `authorize` middleware exists for role-based route protection.
- Express request typing does not yet include `req.user`.

## Implementation Scope

- Add an `authenticate` middleware that verifies the JWT, loads the employee, and rejects deleted or inactive accounts.
- Add route-level `authorize` middleware for `SUPER_ADMIN`, `HR_MANAGER`, and `EMPLOYEE`.
- Extend Express types with a safe authenticated-user shape.
- Ensure auth failures return `401` and role failures return `403`.
- Keep broad role checks at the route level and resource or field-level checks inside services.

## Files Expected To Change

- `backend/src/middlewares/authenticate.ts`
- `backend/src/middlewares/authorize.ts`
- `backend/src/types/express.d.ts`
- `backend/src/routes/`

## Acceptance Criteria

- Protected routes reject missing or invalid auth cookies with `401`.
- Deleted and inactive users lose access even if they still hold an old token.
- Route handlers can use `req.user` without unsafe casting.
- Role middleware supports route declarations such as `authorize("SUPER_ADMIN", "HR_MANAGER")`.
