# 11. Manager Assignment, Circular Reporting Protection, and Organization Reads

Status: Not Started  
Mandatory: Yes  
Depends On: Tasks 7, 9

## Goal

Implement the reporting-hierarchy endpoints: manager assignment, direct reportees, and the organization tree, with backend-enforced circular-reporting prevention.

## Confirmed Current Behavior

- No `PATCH /api/employees/:id/manager` endpoint exists.
- No `GET /api/employees/:id/reportees` endpoint exists.
- No `GET /api/organization/tree` endpoint exists.
- No circular-reporting protection exists in code yet.

## Implementation Scope

- Add manager assignment and manager clearing for Super Admin only.
- Implement backend cycle detection before saving hierarchy changes.
- Add direct reportees reads for Super Admin and HR Manager.
- Add organization tree reads built from one non-deleted employee query instead of recursive database calls.
- Keep deleted employees excluded from hierarchy reads and manager validation.

## Files Expected To Change

- `backend/src/routes/organization.routes.ts`
- `backend/src/controllers/organization.controller.ts`
- `backend/src/services/organization.service.ts`
- `backend/src/routes/employee.routes.ts`
- `backend/src/schemas/organization.schema.ts`

## Acceptance Criteria

- Self-reporting is rejected.
- Reporting cycles are rejected with `409`.
- Manager can be cleared with `managerId: null`.
- Direct reportees exclude deleted employees.
- Organization tree returns root nodes with nested children and no password or internal-only fields.
