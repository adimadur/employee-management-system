# 4. Shared API Responses, Error Handling, and Security Middleware

Status: Not Started  
Mandatory: Yes  
Depends On: Task 1

## Goal

Establish the shared backend behavior for responses, errors, middleware ordering, cookies, CORS, and security headers before protected routes are implemented.

## Confirmed Current Behavior

- No shared success-response helper exists.
- No application error type or central error middleware exists.
- Helmet, CORS, cookie parsing, and JSON body limits are not configured.

## Implementation Scope

- Add standardized success-response helpers that match the repository contract.
- Add an `AppError` pattern and a final Express error handler.
- Map validation failures, duplicate constraints, auth failures, forbidden actions, and unexpected errors consistently.
- Configure `helmet`, `express.json`, `cookie-parser`, and exact-origin CORS with credentials.
- Add shared cookie option helpers for auth cookie set/clear operations.

## Files Expected To Change

- `backend/src/app.ts`
- `backend/src/config/cors.ts`
- `backend/src/middlewares/error-handler.ts`
- `backend/src/middlewares/not-found.ts`
- `backend/src/utils/api-response.ts`
- `backend/src/utils/app-error.ts`
- `backend/src/utils/cookies.ts`

## Acceptance Criteria

- The backend can return contract-consistent success and error responses.
- CORS is configured for credentialed requests without wildcard origins.
- Unexpected errors are logged safely and do not leak internals to clients.
- Shared middleware order is clear and ready for auth-protected routes.
