# 10. Employee Soft Delete and Manager Reassignment

Status: Not Started  
Mandatory: Yes  
Depends On: Task 9

## Goal

Implement the delete workflow as a soft delete with safe authorization and deterministic manager cleanup.

## Confirmed Current Behavior

- No `DELETE /api/employees/:id` endpoint exists.
- No soft-delete workflow exists yet.
- No manager reassignment or nulling behavior exists for deleted employees.

## Implementation Scope

- Add `DELETE /api/employees/:id` for Super Admin only.
- Soft delete the target by setting `deletedAt` and `status=INACTIVE`.
- In the same transaction, clear `managerId` for active direct reportees of the deleted employee.
- Prevent destructive reviewer-hostile cases such as deleting the currently authenticated Super Admin if that safeguard is straightforward.
- Return a success message without leaking internal deletion details.

## Files Expected To Change

- `backend/src/controllers/employee.controller.ts`
- `backend/src/services/employee.service.ts`
- `backend/src/routes/employee.routes.ts`

## Acceptance Criteria

- HR Manager cannot delete employees.
- Deleted employees disappear from normal reads, selectors, counts, and hierarchy responses.
- Active direct reportees of a deleted manager are reassigned to `null` in the same transaction.
- Delete behavior is soft delete, not permanent removal.
